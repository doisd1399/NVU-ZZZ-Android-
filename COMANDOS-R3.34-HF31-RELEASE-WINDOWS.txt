Android 1.0.83 / versionCode 83

IMPORTANTE
Use somente a pasta extraída do ZIP HF31. Não misture arquivos de builds anteriores.

PREPARAR-ANDROID-WINDOWS.bat

[OK] PROJETO PREPARADO COM SUCESSO

cd android

android\app\build\outputs\apk\release\

Identidade esperada:

3) Para distribuir como atualização aos usuários existentes:
- assine com a MESMA keystore/certificado de produção já usado pela NVU;
- não altere applicationId;
- versionCode 83 deve ser maior que o instalado no aparelho.

4) O que a HF31 muda no GTO Observe:
- RESULT_OK do compartilhamento é vinculado ao serviço imediatamente;
- enquanto o token MediaProjection continuar válido, falta de frames NÃO derruba a autorização;
- ImageReader/Surface/Handler são reconstruídos na mesma autorização;
- stalls repetidos continuam tentando indefinidamente na mesma sessão válida;
- o watchdog de frames não depende de UsageStats dizer que o GTO está em foreground;
- WAITING_FREIGHT é recuperado se o serviço Android for recriado;
- falha transitória ao promover o Foreground Service não encerra o observador;
- host de consentimento tolera OEM lento (janela 9 s / até 80 tentativas de estabilização);
- se o Android realmente revogar MediaProjection, o NVU volta a abrir a confirmação automaticamente quando o GTO estiver em contexto seguro.

LIMITAÇÃO DO ANDROID
Se o próprio Android revogar o token MediaProjection (onStop), matar o processo ou exigir novo grant, o sistema operacional exige uma nova confirmação humana em “Compartilhar”. O NVU pode abrir essa tela automaticamente, mas não pode confirmar o botão do Android pelo usuário. Enquanto o token válido estiver vivo, a HF31 não deve pedir nova autorização por simples falta de frames.


HF31 — CORREÇÃO CRÍTICA DO BOTÃO FLUTUANTE
- o alvo “Remover e parar NVU” pertence a uma única geração de gesto;
- ACTION_CANCEL, multipointer, detach do overlay, remoção da task e timeout limpam o alvo sem parar o observador;
- um gesto iniciado sobre o GTO não pode se tornar destrutivo ao sair do GTO;
- ACTION_UP só para o observador com pointer correto, geração correta, alvo destacado, geometria dentro e movimento recente;
- MediaProjection/viagem permanecem independentes do lifecycle visual da bolinha.
