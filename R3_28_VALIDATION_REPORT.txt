ROOT CAUSE FROM DEVICE EVIDENCE
- Native status was WAITING_FREIGHT while screen analysis was paused/outside GTO.
- Capture diagnostic was stuck at 1220x2712 / 0 of 3 stable frames while GTO was landscape.
- MediaProjection was being requested before the simulator had fully become the visible landscape task.
- Result: actual freight pixels were not promoted to the live detector; list/selection notices could not fire.

R3.28 FIX
- Open GTO first, request capture consent only after confirmed GTO foreground.
- Landscape, isolated permission activity for whole-display capture.
- Rotation-aware initial capture size.
- Bounded Android 14+ fallback if captured-content resize callback never arrives.
- Expected IDLE->WAITING_FREIGHT launch preparation no longer flagged as state corruption.
- Senior Panel entry always visible inside admin-only layout; server-backed Senior gate preserved.
