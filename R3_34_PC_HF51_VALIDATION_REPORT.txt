FIDELIDADE DOS ÁUDIOS
=====================
Os dois MP3 enviados pelo usuário foram copiados BYTE A BYTE para res/raw.
Não houve TTS, regravação, normalização, recompressão, mudança de velocidade, pitch ou volume.
O workflow GitHub HF51 abre o APK gerado e compara o SHA-256 de cada MP3 interno com o SHA-256 dos arquivos aprovados. O build falha se qualquer byte for diferente.

INTEGRAÇÃO
==========
NvuAudioManager continua sendo uma extensão passiva. Ele não lê frames, não executa OCR, não conhece MediaProjection e não decide estados do GTO.

SISTEMA_PRONTO:
GtoObserverService.transitionConfirmedFreightToTripInProgress()
 -> estado TRIP_IN_PROGRESS
 -> emitSystemReadyForDepartureIfEligible()
 -> NvuAudioManager.playReadyVoice(eventId)

VIAGEM_CONCLUIDA:
fluxo de resultado existente
 -> parseResultScreen() certifica Concluído
 -> resultado é persistido com commit()
 -> emitTripCompletedVoiceIfEligible()
 -> NvuAudioManager.playTripCompletedVoice(eventId)
 -> fluxo HF49 continua scheduleAutoFinalizeCertifiedResult(0L)

O áudio de conclusão NÃO substitui, atrasa nem comanda o envio automático.

ANTI-REPETIÇÃO E CONCORRÊNCIA
=============================
- Cada frase usa eventId derivado do sessionId da viagem.
- lastReadyVoiceEventId e lastTripCompletedVoiceEventId são persistidos separadamente.
- queuedOrPlayingEventIds impede duplicação enquanto a fala está tocando ou aguardando.
- Frames/callbacks repetidos da mesma tela não repetem voz.
- Uma nova sessionId permite novo aviso.
- Os dois áudios usam fila FIFO no NvuAudioManager para nunca falarem sobrepostos.
- Não há Thread.sleep(); o detector continua funcionando durante a reprodução.
