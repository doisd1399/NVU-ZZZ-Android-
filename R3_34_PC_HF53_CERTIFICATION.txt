NVU R3.34-PC-HF53 — CERTIFICAÇÃO DE FONTE / FLUXO CRÍTICO
Data: 18/08/2026
Android: 1.0.105 (versionCode 105)
Web: 2.3.9

OBJETIVO
Eliminar a combinação observada de viagem concluída preservada localmente, viagem anterior em retry/estado fantasma e fallback por print com progresso enganoso.

CAUSAS COBERTAS
1) Backend atual do Google AI Studio estava pré-HF14 e rejeitava destinationCompany vazio. Em rotas válidas sem empresa de destino, registerGtoTrip retornava invalid-argument e a fila durável permanecia em retry.
2) HF51 podia manter ponteiros de "anterior em envio" mesmo após ACK/remoção real da fila. HF53 preserva byte-a-byte o hardening nativo HF52 que deriva o estado da fila selada, reconcilia marcadores e aceita ACK de qualquer sessão em segundo plano.
3) RecordTrip usava isUploading também durante o envio final da viagem e podia reexibir "Enviando comprovante... 0%" mesmo com o comprovante já enviado. HF53 liga a UI do comprovante apenas a uploadPhase.
4) O export atual continha runtimes Tesseract de 0 bytes. HF53 remove placeholders e faz predev/prebuild validar os assets gerados antes de prosseguir.

INVARIANTES CRÍTICOS CERTIFICADOS
- Tela Concluído certificada -> prova protegida/durável antes do avanço do fluxo.
- Viagem atual -> selada em fila durável independentemente de uma viagem anterior em retry.
- Falha de rede/backend -> não remove a viagem; permanece para retry.
- ACK válido -> remove a sessão exata e reconcilia qualquer marcador antigo.
- Viagem anterior -> nunca impede o selamento da atual.
- destinationCompany -> metadado opcional no Android e no registerGtoTrip.
- ADS -> somente evidência positiva de anúncio/recompensa assistida reprova; botão ADS normal não reprova sozinho.
- Print -> upload do comprovante e envio final da viagem têm estados visuais separados.

LIMITAÇÃO DO AMBIENTE DE CERTIFICAÇÃO
O ambiente desta auditoria não conseguiu alcançar o registry npm. Por isso não foi possível executar aqui um npm ci + build Vite + build TypeScript completo das Firebase Functions nem um Gradle Android real dependente de resolução externa. Nenhum node_modules ou lib parcial é incluído no ZIP final.

O workflow/PC de release DEVE executar com Internet:
- npm ci (ou instalação compatível com o lock do projeto)
- npm run build
- npm --prefix functions install / npm --prefix functions run build
- build Android assinado

A pipeline HF53 contém validações de identidade e de assets. Falha de dependência/OCR agora deve interromper o build em vez de produzir silenciosamente um pacote incompleto.
