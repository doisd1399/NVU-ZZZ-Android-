NVU R3.34-PC-HF60 — TERMINAL SAFE
Android: 1.0.112 (versionCode 112)
Base: HF59 Sync Safe / HF58 Cost Safe
Data: 2026-08-19

INCIDENTE CORRIGIDO
- Cenário de campo: tela Concluído já certificada, modal desaparece, UI mostra
  "Viagem preservada ✓ · finalizando recebimento…" e o fluxo pode ficar preso
  quando gtoForeground/screenAnalysisPausedOutsideGto oscila.

CAUSA RAIZ
- resolveCertifiedResultExitFromFrames() bloqueava indefinidamente a resolução
  terminal enquanto o foreground nativo estivesse incerto.
- confirmNormalResultAutomatically() repetia a mesma dependência de foreground
  mesmo depois de existir prova certificada + latch terminal durável.
- o recovery de selagem da fila HF59 era acionado principalmente pelo polling de
  foreground, deixando uma segunda janela de dead-end em OEMs com foreground stale.

CORREÇÃO HF60
1. Failsafe terminal armado no momento em que a tela Concluído é certificada.
2. O failsafe é independente do foreground e sobrevive a restart pela prova durável.
3. Evidência positiva de anúncio assistido continua bloqueando registro normal.
4. Toque ADS mantém a janela máxima já aprovada antes de fallback normal.
5. Snapshot imutável do frete é exigido/restaurado antes da finalização.
6. A conclusão terminal é persistida com commit síncrono antes de RESULT_CONFIRMED.
7. RESULT_CONFIRMED que ainda não conseguiu selar a fila recebe retry local agendado
   diretamente, sem depender do motorista voltar a uma tela específica.
8. Functions HF58 permanecem byte-identical; não há novo deploy de Functions.
9. OCR/ML Kit, lista de fretes, seleção, bolha e mensagens HF57 permanecem preservados.

OBSERVAÇÃO DE BUILD
O gate verify:release completo neste ambiente chegou até os testes que dependem de
functions/lib e parou porque as dependências npm das Functions não estão instaladas
neste container. Isso não é uma falha funcional HF60. O workflow GitHub incluído faz
npm ci + build das Functions antes do gate e permanece fail-closed: se compilação,
testes, Gradle, assets, assinatura ou identidade falharem, o APK release não é entregue.

DEPLOY
- APK Android HF60 somente.
- Não redeployar Functions apenas por HF60.
- Não é necessário novo deploy Web/Netlify por HF60.
